Retrieval-Augmented Generation (RAG) is an AI framework that combines information retrieval with text generation. Instead of relying solely on knowledge baked into a language model during training, RAG fetches relevant documents from an external knowledge base at query time and uses them as context for generating answers.

The core idea is simple: when a user asks a question, the system first searches a document store for the most relevant passages, then passes those passages along with the question to a language model (LLM). The LLM uses that retrieved context to produce a grounded, accurate answer rather than hallucinating from memory alone.

RAG was introduced in a 2020 paper by Lewis et al. at Facebook AI Research. It has since become the dominant approach for building question-answering systems over private or up-to-date document collections, because it avoids the need to retrain or fine-tune an LLM whenever the underlying data changes.

A typical RAG pipeline works as follows. First, documents are split into smaller chunks (e.g., paragraphs or fixed-size windows). Each chunk is converted into a dense vector (embedding) using a neural encoder like a Sentence Transformer. These vectors are stored in a vector database such as FAISS, Pinecone, or Weaviate. At query time, the user's question is embedded using the same encoder, and the vector store performs a nearest-neighbor search to return the top-k most similar chunks. Those chunks are concatenated into a context block, injected into a prompt template, and sent to the LLM, which generates the final answer.

The main advantages of RAG over pure parametric LLMs are freshness (you can update the knowledge base without retraining), verifiability (you can show users the source chunks), and reduced hallucination (the model is anchored to real retrieved text).
